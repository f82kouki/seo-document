# 執筆フロー（X発掘 → Web検索 → 執筆）

> 美容×SNS×UGC領域のSEO記事を書くときの標準フロー。今後の執筆時はこのファイルを最初に読むこと。
> 体裁・中立性ルールの「本体」は [system.md](system.md)。本ファイルは「調査〜執筆の進め方（プロセス）」を定める。

## このフローの要点（一言で）

**X（旧Twitter）は「いま需要のあるキーワードを見つける発掘源」。記事の参考文献・数値の出典は、そのキーワードでWeb検索してヒットした記事を実際に開いて裏取りしたものを使う。**
X投稿そのものを参考文献・引用元にはしない（過去にこれを取り違えたので注意）。

---

## ステップ0：前提を確認

- 体裁・中立性・規制ガイドは [system.md](system.md) に従う（見出し`■`／小見出し`▸`／箇条書き`・`、リード冒頭は読者の悩みを「」で提起、FAQは`Q.`/`A.`、末尾に「※公開前チェック」）。
- 既存記事と**テーマが重複しないか**を `output/drafts/` で確認してから書く。
- 既定の保存先は `output/drafts/{slug}.md`。

---

## ステップ1：Xでキーワードを発掘（Playwright）

目的は「全件を読む」ことではなく「活発なキーワード／ハッシュタグの当たりを付ける」こと。

1. `mcp__playwright__browser_navigate` で検索URLを開く
   例：`https://x.com/search?q=コスメ&src=typed_query&f=top`（`f=top`=話題、`f=live`=最新）
2. スナップショットは冗長なので、`mcp__playwright__browser_evaluate` で投稿本文とハッシュタグだけ抽出して集計する：
   ```js
   () => {
     const tags = {};
     document.querySelectorAll('a[href*="/hashtag/"]').forEach(a => {
       const t = a.innerText.trim(); if (t.startsWith('#')) tags[t] = (tags[t]||0)+1;
     });
     const posts = Array.from(document.querySelectorAll('article')).slice(0,10)
       .map(a => a.innerText.replace(/\n+/g,' ').slice(0,180));
     return { hashtags: tags, samplePosts: posts };
   }
   ```
3. 複数の語（例：コスメ／メンズコスメ／パーソナルカラー診断 など）で活発さを見て、**SEO記事化できるテーマを3つ程度に絞る**。
4. 終わったら `mcp__playwright__browser_close`。

**Xでの注意（厳守）**
- ユーザーのログイン済みセッションを使う場合がある。**閲覧・検索のみ**。いいね・リポスト・フォロー・投稿・DM等の操作は一切しない。

**良いキーワードの条件**
- Xで実際に活発（投稿・ハッシュタグが多い）／検索されそう（SEO適性）／既存18本と重複しない。

## ステップ2：キーワードでWeb検索（WebSearch）

- 発掘した各キーワードを、補助語を足して `WebSearch` にかける。
  例：「韓国コスメ なぜ人気 理由 Qoo10 メガ割 とは SNS」「メンズコスメ 市場規模 2025 始め方」「パーソナルカラー診断 とは 4タイプ 料金」
- 返ってきた上位記事から、一次情報・権威性の高いもの（公式・調査会社・専門メディア）を参考候補にする。

---

## ステップ3：ヒット記事を開いて裏取り（WebFetch）

- 候補URLを `WebFetch` で実際に開き、数値・定義・出典・調査年を抜き出す。
- **失敗時の対処**：404／証明書エラー／別ホストへのリダイレクトが起きたら、代替URL（リダイレクト先・別ソース）で取り直す。
- **採用するのは「実際に開いて到達・内容を確認できたURLだけ」。** 開けなかったURLは参考リンクに載せない。リダイレクトされた場合は、最終的に開けた実URLを記載する。

---

## ステップ4：執筆

体裁は [system.md](system.md) と既存ドラフトに合わせる。固定構造：

```
{タイトル}

狙いキーワード：{X発掘キーワード}
カテゴリ：{カテゴリ}

{リード：読者の悩みを「」で提起 → 公開情報をもとに整理する宣言}

■ {見出し}
▸ {小見出し}
・{箇条書き}
…
■ よくある質問（FAQ）
Q. … / A. …

■ まとめ（①②③で凝縮）

■ 参考リンク（公式・一次情報を優先）
・本記事のテーマ発掘元：X（旧Twitter）で「○○」を検索し…確認（調査日：YYYY年MM月DD日）
・{媒体名「記事名」：URL}  ← ステップ3で開いて確認したURLのみ

────────────────────────
※公開前チェック
・{数値は出典・調査時点に基づく旨／最新で再確認}
```

**執筆ルール（重要）**
- **テーマ外のことは書かない。** ステマ規制・薬機法は、それ自体が記事テーマでない限り解説セクションを置かない（→ メモ「compliance-proportion」）。UGCの二次利用に関わる場合のみ「二次利用は本人の許諾を取得」をFAQ/末尾チェックに1行残してよい。
- 数値は必ず**出典・調査時点を明記**。市場規模など調査会社で定義・数値が異なるものは「対象範囲」も添える。
- **URL・数値を新規生成（捏造）しない。** 参考リンクはステップ3で開いたURLのみ。
- 参考リンクの先頭に「テーマ発掘元：X検索（調査日）」を1行入れ、調査経路を透明化する。
- 化粧品の効果は断定しない（使用実感・印象の範囲で書く）。

## ステップ5：自点検

書き終えたら以下を確認し、該当あれば本文修正：
1. 体裁（`■▸・`／リード「」／FAQ／まとめ①②③／参考リンク／※公開前チェック）が揃っているか
2. 参考リンクが「実際に開いて確認したURLのみ」か（新規生成・到達不可URLが無いか）
3. 数値に出典・調査時点が付いているか
4. テーマ外のコンプラ解説を入れていないか（compliance-proportion方針）
5. 中立性（他をことさら貶めていないか）

---

## やらないこと

- gitの操作（コミット・プッシュ等）は、指示が無い限りしない。
- Xでの操作（いいね・投稿・フォロー等）はしない（閲覧・検索のみ）。
- 開けなかったURL・記憶ベースの数値の掲載。
