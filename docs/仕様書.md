# 仕様書：美容マーケ向け比較記事SEO半自動システム（beauty-seo-articles）

> 本書は実装済みコード（`src/*.ts`・`package.json`・`data/`・`prompts/`）を読み取って作成した動作仕様書です。設計意図は [作戦書v4.md](../作戦書v4.md) を参照。
> 末尾に「⚠️ 作戦書との差分」として、実装が設計意図とズレている箇所を列挙しています。
> 対象コミット時点のソースに基づきます（作成日：2026-06-03）。

---

## 0. システム全体像

役割分担は「**調査＝スクリプト（API課金ゼロ）／執筆＝Claude Code（人間が指示）**」のハイブリッド。

```
discover.ts        → 比較対象サービスを発掘 → output/candidates/{kw}.csv（人間が approve）
  └ --commit       → approve=y を data/tools.csv に追記
pipeline.ts (prep) → topics.csv の todo を調査 → output/research/{slug}.json + output/prompts/{slug}.md
  ├ research.ts    → SERP起点（serp.ts）＋ 公式直叩き（officialFetch.ts）＋ 共起語
  └ promptBuilder.ts → system.md + template.ts + research + 鮮度文面 → 執筆プロンプト1枚
（人間）Claude Code で prompts/{slug}.md を読んで執筆 → output/drafts/{slug}.md に保存
check.ts (check)   → drafts の記事を正規表現で再点検（neutrality/freshness/urlValidator を呼ぶ）
```

データの流れ上の不変条件：**記事の数値根拠は `officialData`（公式直叩き）のみ**。SERPは「競合の切り口把握」の起点に限定し、全滅しても例外を投げず degrade で続行する。

### 1-4. `src/serp.ts`（SERP起点取得・degrade必須）

| 関数 | 入力 | 出力 | 処理内容 | エラー時 |
|---|---|---|---|---|
| `urlLooksBlocked(url)` | url:string | boolean | sorry/recaptcha/captcha/consent/challenge を正規表現判定 | なし |
| `decodeDdgHref(href)` | href:string | string | DuckDuckGo の `uddg` パラメータを実URLにデコード | パース不能なら絶対URLのまま返す |
| `decodeBingHref(href)` | href:string | string | Bing `/ck/a` の `u=a1<base64url>` を実URLにデコード | パース不能・非http なら元の href |
| `isAdUrl(url)` | url:string | boolean | DDG `y.js`/`ad_domain`/Bing `aclk` 等の広告URL判定 | なし |
| `fetchDuckDuckGo(ctx,kw,page)` | ctx, keyword, page | `FetchOutcome` | `html.duckduckgo.com/html/` へ **フォームPOST**。HTMLを `setContent` し `.result__a` を抽出 | 403/429 または anomaly/challenge で `blocked:true`。例外は上位 `fetchFromEngine` で捕捉 |
| `fetchViaGoto(ctx,engine,kw,page)` | ctx, 'bing'\|'google', kw, page | `FetchOutcome` | Bing/Google を `goto` し、`#b_results .b_algo h2 a`／`div.g` を抽出。リダイレクト/タイトルで CAPTCHA 検知 | blocked 判定で `blocked:true` |
| `fetchFromEngine(ctx,engine,kw,page=1)` | — | `EngineOutcome` | エンジン別取得→URLデコード→広告除外→重複除去→rank付与 | **例外を投げない**（catch して `results:[]`, note にエラー文） |
| `fetchSerp(keyword,page=1)` | keyword, page | `{engine, results}` | `withContext` 内で serpEngineOrder を順に試行。各試行後に throttle。最初に1件以上得たエンジンを採用 | **全滅時 `engine:'none', results:[]`（例外なし）** |

- 直接実行時（`tsx src/serp.ts --keyword=...`）：各エンジンの取得状況と `fetchSerp` の採用エンジンをコンソール表示するデモ。

## 2. npm コマンド仕様

`package.json` の scripts。すべて `tsx`（TypeScript 直実行）。**Anthropic API は一切呼ばない**。

| コマンド | 実体 | 何をするか | 前提 | 生成物 |
|---|---|---|---|---|
| `npm run discover -- --keyword="..."` | `tsx src/discover.ts` | SERP上位の比較記事からサービス名を抽出し、公式URLを推定・検証して**承認待ち候補CSV**を出力 | Playwright(chromium) 導入済み。ネットワーク到達（SERPが全滅すると候補なし） | `output/candidates/{keyword}.csv`（approve 既定 `?`） |
| `npm run discover -- --commit [--keyword="..."]` | `tsx src/discover.ts` | 候補CSVの `approve=y` 行を `data/tools.csv` に追記（既存名は名寄せでスキップ） | 候補CSVが存在し approve を編集済み | `data/tools.csv` に追記 |
| `npm run prep -- --count=N [--only=slug]` | `tsx src/pipeline.ts` | topics.csv の todo を調査し、research.json と執筆プロンプトmd を生成。status を ready/error に更新 | topics.csv 存在。tools.csv（任意・無ければ SERP起点のみ）。Playwright 導入済み | `output/research/{slug}.json`、`output/prompts/{slug}.md`、topics.csv の status 更新 |
| `npm run check -- --file=output/drafts/{slug}.md` | `tsx src/check.ts` | Claude Code が書いた記事を正規表現で再点検し、末尾に警告ブロックを追記 | 対象 md が存在。tools.csv（他社名）・ng-words.json 必須。research.json があれば価格・URL照合も実施 | 対象 md の末尾に `<!-- COMPLIANCE WARNINGS -->` ブロックを追記（再実行で置換） |
| `npm run typecheck` | `tsc --noEmit` | 型チェックのみ（成果物は出さない） | TypeScript 導入済み | なし |

> 補足：`tsx src/serp.ts --keyword=...`、`tsx src/research.ts --keyword=... --slug=...` は npm script 未登録だが、各ファイルの直接実行で手動検証用デモが動く。

### セットアップ前提（共通）
- `npm install`
- `npx playwright install chromium`（discover/prep が chromium を使うため必須）
- APIキー・`.env` は不要。

## ⚠️ 作戦書との差分

作戦書v4の設計意図と実装を照合し、ズレ・未実装・挙動差を **重大度順** に列挙する。

### A. 設計意図とズレている（要検討）

1. **ステマ層が参照する note が作戦書と異なる**（§4 check.ts ステマ層）
   - 作戦書：「**topics.csv** の note の `案件/提供/自社PR` フラグと突合」。
   - 実装（`check.ts:stealthCheck` / `loadToolNotes`）：参照しているのは **tools.csv** の note 列で、検出キーワードも「**自社**」のみ。topics.csv の note（実データには「自社サービス含む=ステマ表記必須」）は一切見ていない。
   - 影響：topics 側でステマ指定しても、tools.csv 側に「自社」note が無ければステマ層が発火しない。現状は tools.csv の「自社=PR表記対象」に依存。

2. **景表法（最上級）層に「根拠出典の有無」判定が無い**（§1 リスク2 / §4 景表法層）
   - 作戦書：「根拠となる調査出典が research.json に**無ければ**警告」＝出典があれば許容する条件付き検出。
   - 実装（`check.ts:superlativeCheck`）：research.json の中身を見ず、最上級語があれば**常に**警告。さらに severity は `ng-words.json` 上 `high` だが、コードでは **`mid` 固定**（JSONの severity を使っていない）。
   - 影響：出典付きの正当な最上級も警告化し得る。重大度表記も辞書と不一致。

3. **discover が料金ページURL（pricing_url）を収集しない**（§2-1 / §4 discover.ts 手順2）
   - 作戦書：「公式ドメインと**料金ページURLを自動推定・検証**」。
   - 実装（`discover.ts:resolveOfficialUrl`）：常に `pricingUrl: undefined` を返し、officialUrl も origin（トップ）のみ。料金ページの解決は未実装。
   - 影響：tools.csv に pricing_url が入らず、officialFetch は officialUrl(=トップ) を開くため料金抽出の精度が落ちる。

4. **discover --commit で category が常に空になる**（§5 tools.csv スキーマ）
   - 候補CSVの列は `name,official_url,pricing_url,occurrences,approve,note` で **category 列が無い**。一方 `commit()` は `r.category` を読む（`discover.ts:204`）ため、必ず空文字。
   - 影響：discover 経由で追記された tools.csv 行は category が空になる（手動補完が必要）。

### B. 作戦書に挙げた要素が未実装（任意機能含む）

5. **`data/sources.json`（信頼できる一次情報ドメイン）が存在せず未使用**（§3 ディレクトリ構成）
   - `config.ts:paths.sources` にパス定義はあるが、ファイル実体が無く、どのコードからも読まれていない。urlValidator は sources.json ではなく research.json 由来URLで照合している（こちらの方が厳密ではある）。

6. **サジェスト拡張（suggestqueries）が未実装**（§2-4・任意）
   - `config.ts:suggest` にエンドポイント定義のみ。`suggestqueries.google.com` を叩くコードは存在しない。作戦書でも「任意」扱い。

7. **urlValidator の死活200チェックが未実装**（§4 urlValidator・「任意で」）
   - `validateUrls` は正規化照合のみ。HTTP 200 の死活確認は行わない。

### C. 軽微・実装上の留意点

8. **officialFetch が billingCycle / targetUser を取得しない**（§2-3 / §4 officialFetch）
   - 型 `OfficialData` / `PricingPlan` には `billingCycle`・`targetUser` があり promptBuilder も表示対応するが、`fetchOne` は `targetUser: undefined` 固定で billingCycle も埋めない。「対象ユーザー」「課金サイクル」抽出は未実装。

9. **pipeline のテーマ処理は逐次**（§4 pipeline「Playwright 2並列」）
   - topics ループは直列実行。2並列は `officialFetch.fetchOfficialData` 内（1テーマ内の複数 tool 取得）にのみ適用。「テーマ間 2並列」とは読めない実装（解釈次第だが直列）。

10. **discover の commit 追記が改行を補わない**（`discover.ts:226`）
   - `fs.appendFileSync(paths.tools, (header ? '' : '') + csv)` の `(header ? '' : '')` は無意味な式で、追記前に改行を挿入しない。既存 tools.csv が末尾改行で終わっていれば問題ないが、末尾改行が無いファイルだと最終行と追記行が連結する可能性がある（現データは末尾改行ありで実害なし）。

11. **research.ts が SERP補完で別ブラウザを再起動**（性能上の留意）
   - `fetchSerp`（内部で `withContext`）と `enrichSerpHeadings` 用の `withContext` で chromium を2回起動する。機能上の問題はないが起動コストが二重。

### 差分まとめ

- **設計の根幹（API課金ゼロ／公式直叩きのみを数値根拠／SERP degrade／原子的 status 更新／中立性 high 検出／鮮度ディスクレーマー）はすべて実装され、意図通り。**
- ズレは主に **(A) 検査ロジックの条件付き判定の省略（2のsuperlative、1のステマ参照元）** と **(B/C) discover のURL/カテゴリ収集の作り込み不足** に集中している。記事品質・法務リスクへの直結度では **項目1・2** を優先的に確認することを推奨する。
